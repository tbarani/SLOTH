# test2 — intergranular fission gas bubbles in a Merope polycrystal

Polycrystal version of `test1`, in the spirit of Fig. 4 of D.-U. Kim et al., *Mater. Theory* 6
(2022) 7: a periodic 2D Voronoi/Laguerre polycrystal (5 grains) generated by **Merope**, on the
grain boundaries of which initial gas bubbles grow and interconnect under the Aagesen et al.
phase-field model (CMS 161 (2019) 35-45, same non-dimensionalisation as test1).

## From Merope to a SLOTH mesh

Merope's own `MeshGenerator` is 3D-only, so the 2D polycrystal is meshed through the `geo2d`
tool of the Merope clone (see `/home/tommy/projects/sloth_trials/merope2d/make_mesh.sh`):

```bash
# merope clone+build: /home/tommy/projects/sloth_trials/Merope (built into Merope/install)
$MEROPE/install/bin/geo2d 600 600 5 0 12 poly.geo   # box, ngrains, seed, mesh size
gmsh poly.geo -2 -format msh2 -setnumber Mesh.RecombineAll 1 -o poly.msh
```

`geo2d` computes the exact periodic Laguerre cells from `sac_de_billes`/Merope seeds and writes
a native gmsh `.geo` with

- one `Physical Surface("grain_k")` per crystallite,
- `Physical Curve("box")` on the outer frame,
- `Periodic Line {..} = {..} Translate {..}` pairing opposite box edges,
- a background field grading the mesh size near the grain boundaries.

After `gmsh`, `poly.msh` (format 2.2) carries `$PhysicalNames` (`2 k "grain_k"`), per-element
physical tags = grain id, and `$Periodic`. `RecombineAll=1` gives quads (SLOTH's NC-enabled
mesh path here converts quad meshes). The committed `poly.msh` is such a file (5 grains,
600x600 nm, lc=25 coarse / lc=5 near grain boundaries, ~9k quads). Regenerate it with
`/home/tommy/projects/sloth_trials/merope2d/make_mesh.sh` and copy it here.

## Linking crystallites to phase fields in SLOTH

The mesh is loaded with the GMSH reader and the periodic flag:

```cpp
SPA spatial("GMSH", order_fe, refinement_level, "poly.msh", /*periodic=*/true,
            /*enable_nc_mesh=*/true);
```

MFEM exposes the named physical groups as attribute sets, and each grain order parameter is
initialized from its own attribute set (`Variable`'s attribute-based initial condition projects
the given function on the listed attributes and leaves 0 elsewhere):

```cpp
VAR(s, bcs, "eta_g" + std::to_string(i), Glossary::PhaseField, 2,
    AnalyticalFunctions<DIM>(ic_grain),   // 1 - eta_b(x)
    std::set<std::string>{"grain_" + std::to_string(i)});
```

so `eta_gi == 1` exactly inside grain `i`. The bubble order parameter `eta_b` is initialized
with tanh bubbles placed at midpoints of the mesh edges separating two grains (computed from a
serial copy of the mesh file, identical on every MPI rank).

One kernel change was needed for this: the shared-mesh `SpatialDiscretization` constructor now
also shares the owning mesh's attribute sets (`kernel/include/Spatial/Spatial.hpp`), otherwise
`get_elem_attributes()` is null for variables built on a shared mesh.

## Model and layout

Same three staggered problems as test1 (`OrderParameters` with `NB_GRAINS+1` Allen-Cahn fields,
`MuVac`, `MuGas`), coefficients generated at configure time from `coefficients.json`
(`../test1/generate_coefficients.py -ng 5` with test1's parameters). The json uses the `Sum`
capability of `GenerateCoefficient.py` (`Sum(eta[i]*eta[i], (i, 1, 6))`, cf.
`tests/Studies/multigrains`), so the expressions stay short whatever the number of grains; the
generated F/gradient/Hessian were verified numerically identical (max rel. diff 1e-17) to the
fully expanded form. AMR (Kelly estimator, `MultiVariableMaxAMR`) is attached to the
order-parameter problem (`-amr`, max level `-elm_amr`); the smoke test runs with `-noamr`
because the estimator dominates a one-step run on this small mesh.

## Run

```bash
cd build && make FissionGas2Dtest2 -j4
ctest -R FissionGas2Dtest2            # smoke test: -noamr -t 50 -dtmin 5 -dtmax 5, np 2
# production-style short run with AMR:
mpirun -np 4 tests/Studies/fissiongas/test2/FissionGas2Dtest2 -amr -elm_amr 2 -t 1e4
```

Outputs land in `Saves/Polycrystal/` (VTU series with `eta_g1..eta_g5`, `eta_b`, `h_m`, `h_b`,
`mu_v`, `mu_g`, plus the `*_time_specialized.csv` tables compared by ctest).

Note: the box size printed at startup is read back from the (periodic) mesh vertices, so the
outermost slave vertices are missing and it reads ~594 instead of 600 nm; this only shifts the
periodic images of boundary-near bubbles by a few nm.
