# test5: 3D fission gas bubbles on a Merope Voronoi polycrystal

`test5` is `test4` on a real microstructure. The model is the same three-problem staggered model
of `test0`..`test4`: Allen-Cahn for the eight grain order parameters plus the bubble order
parameter `eta_b`, and the two chemical-potential problems for vacancies and gas. The parameters
are those of Table 1 of L.K. Aagesen, D. Schwen, M.R. Tonks, Y. Zhang, *Phase-field modeling of
fission gas bubble growth on grain boundaries and triple junctions in UO2 nuclear fuel*, Comput.
Mater. Sci. **161** (2019) 35-45, with the single soft curvature k = 2.57e9 J/m3 of D.-U. Kim et
al., *Mater. Theory* **6** (2022) 7. The geometry is the difference: `test4` uses the four-hexagon
cell of Aagesen et al. Fig. 3, `test5` uses a Merope Voronoi (Laguerre) polycrystal with **eight
grains in a 600 x 600 x 280 nm periodic box**, and the initial bubbles are read from a file
written by the mesh-generation script instead of being placed inside `main.cpp`.

Lengths are in nm, times in 0.1 s, energy densities in 64e9 J/m3. `coefficients.json` is
generated by `../test1/generate_coefficients.py -ng 8` with the Kim curvature
`--kvm/--kgm/--kvb/--kgb 0.04015625` (the same values as `test1`..`test4`: gmm = 1.5, gmb = 0.922,
kappa = 0.52734375, Va = 0.0409, cv/cg equilibrium concentrations, eps = 1e-12).

## Mesh: `poly.msh`

`generate_mesh.sh` produces the two committed inputs, `poly.msh` and `bubbles.txt`, in the same
three stages as `test4`:

1. `make_voronoi3d.py` builds the geometry: eight grain seeds in the periodic cell, the exact
   periodic Laguerre (Voronoi) cells they define, and a gmsh `.geo` file with one surface per
   grain, the outer box faces, and a Background Field that grades the mesh from fine elements on
   the grain boundaries and around the bubbles to coarse elements inside the grains. The seeds
   and grading parameters are pinned in the script.
2. `gmsh -3 -format msh2` meshes the cell (gmsh 2.2, readable by MFEM 4.9, as for `test4`).
3. A finalize step tags the tetrahedra with the physical volumes `grain_1..8` and the boundary
   triangles with the physical surface `box`, then appends a `$Periodic` section **after
   `$Elements`**, pairing the opposite box faces in x, y and z by nearest-neighbour node
   coordinates. The section order matters: MFEM 4.9's v2 gmsh reader applies the slave to master
   mapping only to the elements read so far and marks the mesh curved, so the slave vertex
   coordinates stay in the `Nodes` field and the wrapping elements keep the right geometry.

`main.cpp` loads the file with `SPA spatial("GMSH", 1, refinement, "poly.msh", periodic, true,
true)` (non-conforming refinement allowed for AMR), shares that mesh with the two chemical
potential problems and with one spatial discretization per grain, and initializes grain i on the
attribute set `grain_i`. The box size for the periodic images of the bubbles is passed with
`-lx/-ly/-lz`; the defaults (600/600/280) match the committed mesh.

## Initial bubbles: `bubbles.txt`

`generate_mesh.sh` also writes `bubbles.txt`: one `x y z r` line per bubble in nm, `#` for
comments. The placement follows Section 3.1 of Aagesen et al. on the Voronoi geometry:

- random grain-face bubbles at NGB = 20/um2, with the centres on the Voronoi grain faces;
- triple-line bubbles at NTJ = 7.14/um on the grain edges (the triple lines of the 3D
  polycrystal), i.e. the `test4` reference spacing lTJ = Lz/2 = 0.14 um;
- all bubbles are spheres of radius 44 nm, centres at least 88 nm apart (2r, periodic images
  included), fixed seed 2019 so the file is reproducible.

`main.cpp` reads the list with `-bf` (default `bubbles.txt`) and builds the same tanh bubble field
as `test4`, `eta_b = max(0.5 - 0.5 tanh(2 (r - r_bubble) / 30))` over all bubbles and their 27
periodic images, with the 30 nm interface width of the model. The grain fields are
`eta_gi = 1 - eta_b` on `grain_i` and zero elsewhere. The bubbles are tanh spheres, not regions
of the mesh: the diffuse interfaces do not have to follow the mesh, which is what allows the mesh
to be a plain Voronoi tessellation. The bubbles rapidly equilibrate to lenticular shapes on the
grain faces and elongated triangular shapes on the triple lines.

## Kim 2022 source ratio

The gas production rate is S_g = 2.35e-10 (times `-sf`). Kim et al. 2022 take the vacancy source
to be four times the gas one, S_v = 4 S_g, whereas Aagesen et al. 2019 used S_v = 10 S_g. `test5`
follows Kim: `-svratio` (alias `--source_vacancy_ratio`, default 4.0) sets
`source_vac = svratio * source_gas`.

## AMR

AMR is **on by default** (`-amr`, `-noamr` to disable). The order-parameter problem is refined
with the Kelly estimator of a diffusion problem on each field, maximized over the fields
(`MultiVariableMaxAMR`, as in `test1`/`test2`), with `nc_limit 0`, `max_preref_cycles 3`,
`-erm_amr` = 1e-4 and `-elm_amr` = 2. On the unstructured Voronoi mesh AMR is what puts fine
elements at the grain boundaries and around the bubbles, so the tessellation itself can stay
coarse and does not need to be refined by hand. Production runs use `-amr -elm_amr 2`; the ctest
smoke run uses `-noamr`, because the estimator dominates the cost at that size.

## Run

```bash
cd build && make FissionGas3Dtest5 -j4
ctest -R "FissionGas3Dtest5"        # smoke: -noamr -t 50 -dtmin 5 -dtmax 5, mpirun -np 4
# NOTE: the smoke test (and its comparisons) are registered only on machines with >= 32
# logical cores (cmake_host_system_information); the 104k-tet mesh takes ~45 min at np 4 on
# 8 cores. On smaller machines ctest simply skips it, the executable is still built.
# production-style short run with AMR:
mpirun -np 4 tests/Studies/fissiongas/test5/FissionGas3Dtest5 -amr -elm_amr 2 -t 1e4
```

The mesh and bubble file default to `poly.msh` and `bubbles.txt` in the working directory (they
are copied next to the executable by CMake); `-m` and `-bf` override them. Outputs land in
`Saves/Voronoi/` (calculation path `Voronoi`): VTU series with `eta_g1..eta_g8`, `eta_b`, `h_m`,
`h_b`, `mu_v`, `mu_g`, plus the `*_time_specialized.csv` tables.

## References

`ref/` holds the two columns compared by ctest, generated from the committed `poly.msh` and
`bubbles.txt` with exactly the smoke command. The specialized files are appended to, not
truncated, so the run must start from a clean `Saves` (the ctest command does `rm -rf Saves`).
To regenerate them, run the smoke test and copy
`Saves/Voronoi/OrderParameters_time_specialized.csv` to `ref/op_time_specialized.csv` and
`Saves/Voronoi/MuGas_time_specialized.csv` to `ref/mug_time_specialized.csv`. The comparison
tests are registered at configure time only when both reference files exist AND the machine has
>= 32 cores. Columns 3-4 (bubble
inventory) are compared at 1e-8 relative, the gas inventory and density at 1e-2: the iterative
solves are not bit-reproducible across runs (about 1e-4 relative in the energy/mu columns), and
the mu columns are near zero at early times where a relative criterion is meaningless.
